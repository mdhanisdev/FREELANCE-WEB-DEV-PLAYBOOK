# MAINTENANCE & ADD-ONS [ RECURRING INCOME ]
------------------------------------------------------------------------

## OVERVIEW

Delivery isn't the end of the money — it's the start of recurring income.
First you honor the free warranty window. Then you convert the client to
a monthly retainer paid in advance, and you bill new features as separate
mini-projects. One good client becomes predictable monthly revenue plus
add-on lumps, all with far less selling than finding a new client.

------------------------------------------------------------------------

## THE MAINTENANCE TIMELINE

```text
  WARRANTY (free)     RETAINER (monthly)      ADD-ONS (per project)
 ┌───────────────┐   ┌──────────────────┐   ┌──────────────────┐
 │ 14-30 days    │   │ paid in advance  │   │ new feature =    │
 │ free bug fix  │──▶│ Basic/Growth/Pro │──▶│ mini-proposal    │
 │ (scope only)  │   │ recurring income │   │ + deposit        │
 └───────────────┘   └──────────────────┘   └── loops 03→05 ───┘
```

## 1. WARRANTY WINDOW FIRST

```text
□ Free bug fixes for the agreed period (from step 12)
□ Bug = agreed-scope feature not working. Fix it, no charge.
✓ New requests during warranty that aren't bugs → quote as add-ons.
✓ As the window closes, pitch the retainer (see below).
```

------------------------------------------------------------------------

## 2. THE MONTHLY RETAINER (paid in advance)

Software rots: dependencies age, security holes open, things drift. A
retainer keeps their site healthy and keeps you paid. Always billed at
the START of the month.

```text
┌─────────┬────────────────────────────────────────────────────┐
│ BASIC   │ dependency updates + security patches               │
│         │ + uptime monitoring + VERIFIED backups              │
├─────────┼────────────────────────────────────────────────────┤
│ GROWTH  │ everything in Basic                                 │
│         │ + a few hours of changes/tweaks per month           │
├─────────┼────────────────────────────────────────────────────┤
│ PRO     │ everything in Growth                                │
│         │ + priority support + monthly feature work           │
│         │ + a monthly report (uptime, changes, health)        │
└─────────┴────────────────────────────────────────────────────┘
```

```text
✓ "Verified backups" = you actually test a restore, not just
  trust that the backup ran.
✓ Paid in advance → no chasing invoices, no unpaid work.
✓ Unused hours don't roll over (state this in the contract).
```

------------------------------------------------------------------------

## 3. ADD-ON FEATURES (billed per project)

A retainer covers upkeep and small tweaks — NOT whole new features. Each
new feature is its own small project.

```text
□ New feature request → write a mini-proposal (scope + price + timeline)
□ Take a deposit before starting
□ Build it, then loop back through the pathway:
      03 - PROPOSAL & SCOPE
      04 - CONTRACT & DEPOSIT
      05 - BUILD  (and onward through testing → launch → delivery)
□ Bill the balance on delivery, same as any project
✓ This keeps scope creep out of the retainer and your hours paid.
```

------------------------------------------------------------------------

## 4. ACCESS FOR MAINTENANCE

You handed over all accounts at delivery (clean hands). To do
maintenance, the client re-invites you — with the access they choose.

```text
□ Client re-invites you as a collaborator / team member
    ✓ repo access, hosting, and whatever the retainer needs
□ Scope the access to the work; nothing more
□ When the retainer ends, they remove you again → clean hands restored
✓ You never silently kept keys "just in case." Access is granted,
  logged, and revocable.
```

------------------------------------------------------------------------

## 5. AUTOMATE THE BORING PARTS

```text
□ Renovate → automated dependency-update PRs (review + merge)
□ Sentry → errors surface without you watching
□ BetterStack → uptime alerts, no manual checks
□ Recurring invoice → retainer auto-bills each month
✓ The less manual the retainer, the higher your effective rate.
```
