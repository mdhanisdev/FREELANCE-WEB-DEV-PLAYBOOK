# REMIX / REACT ROUTER 7 SETUP [ WEB-STANDARDS FULL-STACK ]
------------------------------------------------------------------------
## STEP 1 : Scaffold The Project

Remix has merged into React Router 7 (framework mode). Scaffold with the
official template.

```bash
pnpm dlx create-react-router@latest my-app
cd my-app
pnpm install
pnpm dev
```

Windows note: `pnpm dlx` works identically in PowerShell and Git Bash;
if a template download stalls behind a proxy, set `HTTPS_PROXY` first.

## STEP 2 : Project Structure

```text
app/
├── root.tsx             # <html> shell, <Links>, <Scripts>, <Outlet/>
├── routes/              # file-based routes
│   ├── _index.tsx       # "/"
│   ├── about.tsx        # "/about"
│   ├── posts.$slug.tsx  # "/posts/:slug"
│   └── dashboard.tsx    # "/dashboard" (can nest via layout)
├── routes.ts            # optional explicit route config
└── entry.server.tsx     # streaming SSR entry
```

Dotted filenames create URL segments; `$param` is a dynamic segment and
`_prefix` denotes a pathless (layout-only) route.

## STEP 3 : Loaders — Read Data On The Server

A `loader` runs only on the server and provides data before render.

```tsx
// app/routes/posts.$slug.tsx
import type { Route } from "./+types/posts.$slug";
import { useLoaderData } from "react-router";

export async function loader({ params }: Route.LoaderArgs) {
  const post = await db.post.findUnique({ where: { slug: params.slug } });
  if (!post) throw new Response("Not Found", { status: 404 });
  return { post };
}

export default function Post() {
  const { post } = useLoaderData<typeof loader>();
  return <article><h1>{post.title}</h1></article>;
}
```

Types in `./+types/*` are generated by `pnpm typecheck` / dev server.
------------------------------------------------------------------------
## STEP 4 : Actions & Forms — Write Data

`action` handles mutations from a standard `<Form>`; no client fetch code.

```tsx
// app/routes/contact.tsx
import { Form, redirect } from "react-router";
import type { Route } from "./+types/contact";

export async function action({ request }: Route.ActionArgs) {
  const form = await request.formData();
  const email = String(form.get("email")); // e.g. user@example.com
  await db.lead.create({ data: { email } });
  return redirect("/thanks");
}

export default function Contact() {
  return (
    <Form method="post">
      <input name="email" type="email" required />
      <button type="submit">Send</button>
    </Form>
  );
}
```

Forms work without JavaScript (progressive enhancement) and are enhanced
into client transitions automatically when JS loads.

## STEP 5 : Data Flow Overview

```text
Navigation / <Form> submit
   │
   ▼
action() ──(mutate)──► redirect or return data
   │
   ▼
loader() re-runs for affected routes (server)
   │
   ▼
useLoaderData() / useActionData() ──► component re-renders
```

## STEP 7 : When To Choose It Over Next.js

Pick React Router 7 / Remix when web-standards and data mutations lead:
nested routing, `Request`/`Response` primitives, `<Form>`-driven writes,
and painless progressive enhancement. It runs anywhere a JS server or
edge runtime runs. Choose Next.js instead when you want React Server
Components, its large ecosystem of integrations, ISR/static caching out
of the box, or first-class Vercel deployment.
------------------------------------------------------------------------
## BEST PRACTICES

```text
✓ Keep data reads in loaders and writes in actions — never mix in effects
✓ Use <Form> before reaching for client fetch; enhance, don't replace
✓ Throw Response objects for 404/redirect control flow in loaders
✓ Rely on generated ./+types for end-to-end type safety
✓ Split UI with nested routes and pathless layout routes
✓ Revalidate via loader re-runs, not manual client cache juggling
✓ Validate and coerce formData; never trust raw input
✓ Run pnpm typecheck (typegen) in CI
```
